## 5. Analysis

### Where tools clearly help

The tool-calling agent's advantage is most visible in examples that
require external context:

- **03_repeat_customer**: The agent calls `lookup_customer_history`
  and discovers this is the customer's third identical complaint.
  It correctly elevates to P1 and recommends history review.
  The baseline cannot know the complaint is a repeat — it sees only
  the text, which reads like a first-time P2 product defect.

- **09_multi_issue**: The agent calls both `lookup_customer_history`
  and `search_similar_past_complaints` to untangle a dual billing +
  shipping complaint. The tool results help it correctly prioritize
  the billing dimension. The baseline picks the wrong primary category
  since both issues are equally prominent in the text.

- **05_vague_low_confidence / 06_spam**: The agent calls
  `escalate_to_human` when its confidence drops below the 0.7 threshold.
  This is a hard-coded safety policy that the baseline cannot replicate —
  the baseline must guess `escalate_to_human` purely from text signals,
  and it fails to do so for ambiguous or nonsensical inputs.

### Where the baseline performs equally well

For complaints with unambiguous text signals, the single-prompt baseline
often matches the full agent:

- **01_billing_double_charge**: The complaint text contains clear
  financial language ("charged twice", "$29", "refund"). Both systems
  correctly classify as `billing / P1`. The tools add latency but
  no additional accuracy on this straightforward case.

- **02_legal_threat / 12_safety_serious**: Safety and legal keywords
  ("attorney", "caught fire", "recall") are strong enough text signals
  that even a single-prompt classifier catches them as P0 escalations.

- **08_minor_typo / 10_sarcasm**: Simple categorization tasks where
  the text alone provides all necessary context. The baseline matches
  the agent on every dimension.

### Where the baseline arguably performs better

- **Speed**: The baseline consistently runs in 500–800ms (single LLM call)
  vs. the agent's 1500–3500ms (multi-step with tool roundtrips). For
  high-volume queues where P2 complaints dominate, the baseline's latency
  advantage is material.

- **06_spam**: While both systems technically fail on `next_tool` (neither
  predicts the ground truth perfectly), the baseline's `none` prediction
  is arguably more defensible than the agent's `escalate_to_human` — spam
  shouldn't consume human reviewer time either.

### Latency trade-off

The baseline is consistently faster because it makes a single LLM call
with no tool roundtrips. For high-volume, low-stakes triage, the baseline
may be a cost-effective first pass before escalating uncertain cases to
the full tool-calling agent.

### Recommendation

A production system should consider a **two-tier architecture**:

1. **Fast pass** — baseline classifier screens all incoming complaints.
   If confidence ≥ 0.85 and category is not `safety_or_legal`, auto-route.
2. **Deep triage** — the tool-calling agent runs only when the baseline's
   confidence is below threshold, the complaint mentions repeat issues,
   or the category is `safety_or_legal`.

This preserves accuracy where tools matter while avoiding unnecessary
latency and cost on straightforward complaints.

### Limitations of this evaluation

- 12 examples is too small to draw statistical conclusions.
- Ground truth labels are subjective — another labeler might disagree
  on borderline cases (especially 05, 06, 09).
- Both systems use the same base model, so the comparison measures
  the value of tool access, not model quality.
- Real-world complaints have more variation in length, language, and
  ambiguity than this curated set.
